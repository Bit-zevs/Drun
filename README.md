# Drun · Лабораторная работа 1

Персональный ассистент с собственным циклом нативных вызовов инструментов. CLI и Telegram используют одного владельца, общую очередь SQLite и историю. Python-ядро использует стандартную библиотеку. Дополнительные пакеты разбирают iCalendar и поставляют базу часовых поясов.

## Запуск

Нужны Python 3.11+ и Docker с Linux-контейнерами. Чат работает на локальной [Qwen3 8B](https://ollama.com/library/qwen3:8b), а векторная память использует [Qwen3 Embedding 0.6B](https://ollama.com/library/qwen3-embedding:0.6b). Ключ облачного провайдера не нужен. При первом запуске Docker скачает образы, а Ollama — примерно 6 ГБ весов. Веса сохраняются в томе Docker.

Создайте `.env` из `.env.example`, задайте собственный `LITELLM_MASTER_KEY` с префиксом `sk-` и случайный `DRUN_TOKEN` длиной от 20 символов. В конфигурациях от прежней версии можно удалить `OPENAI_API_KEY`, `CHAT_MODEL` и `EMBED_MODEL`. Сохранённые прежней моделью векторы другой размерности пропускаются при поиске. Чтобы факт снова участвовал в поиске, попросите запомнить его заново.

### 1. Подготовьте проект

Откройте PowerShell в корне репозитория. Полная реализация находится в ветке `lab-1/drun-assistant`. Запустите Docker Desktop и дождитесь готовности Linux-контейнеров.

```powershell
git switch lab-1/drun-assistant
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

Замените шаблонные значения обоих токенов в `.env` и сохраните файл.

### 2. Запустите шлюз и скачайте модели

Для NVIDIA с Docker Desktop на WSL 2 используйте команды ниже. Для CPU задайте `$composeFiles = @('-f', 'compose.yaml')` и выполните остальные строки блока. Дождитесь завершения каждой команды перед следующей.

```powershell
$composeFiles = @('-f', 'compose.yaml', '-f', 'compose.gpu.yaml')
docker compose @composeFiles up -d
docker compose @composeFiles ps
docker compose @composeFiles exec -T ollama ollama pull qwen3:8b
docker compose @composeFiles exec -T ollama ollama pull qwen3-embedding:0.6b
docker compose @composeFiles exec -T ollama ollama list
docker build -t drun-sandbox sandbox
```

В `ps` оба сервиса должны иметь статус `Up`, а `ollama list` должен показать обе модели.

### 3. Запустите и проверьте агента

В первом терминале оставьте сервер запущенным:

```powershell
.\.venv\Scripts\python.exe -m drun serve
```

Во втором PowerShell откройте ту же папку и выполните:

```powershell
.\.venv\Scripts\python.exe -m drun ask "Покажи дерево рабочей папки и прочитай AGENTS.md"
.\.venv\Scripts\python.exe -m drun ask "Прочитай AGENTS.md через Bash и PowerShell в песочнице и покажи оба результата"
.\.venv\Scripts\python.exe -m drun usage
```

[Дашборд расхода](http://127.0.0.1:8765/dashboard) открывается с HTTP Basic. Имя пользователя произвольное, пароль — `DRUN_TOKEN`. REST API сервера доступен только через loopback. Для другого порта передайте одинаковый `--port` серверу и CLI.

### Если запуск прервался

- При конфликте имени `drun-ollama-1` дождитесь окончания другого запущенного `docker compose up` и проверьте `docker compose @composeFiles ps -a`. Если оба сервиса в статусе `Up`, перейдите к скачиванию моделей. Если Ollama имеет статус `Created` или `Exited`, запустите её через `docker compose @composeFiles start ollama`, затем повторите `up -d`.
- Если в журнале LiteLLM после замены ключа появляется `No connected db`, пересоздайте только шлюз командой `docker compose @composeFiles up -d --no-deps --force-recreate gateway`. Перезапустите `drun serve`, чтобы он прочитал свежий `.env`.
- После настройки интеграций в `.env` перезапустите `drun serve`.

## Интеграции

Настройки добавляются в локальный `.env` в корне проекта в формате `ИМЯ=значение`, без внешних кавычек. Храните токены и приватные ссылки в этом файле. После изменений перезапустите `drun serve`.

### Telegram и напоминания

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и запишите выданный токен в `TELEGRAM_TOKEN`.
2. Остановите `drun serve` через Ctrl+C. Откройте личный чат со своим ботом, нажмите Start и отправьте сообщение.
3. В PowerShell из корня проекта выполните команду ниже. Она читает токен из `.env` и выводит только идентификаторы личных чатов с необработанными сообщениями.

```powershell
@'
import json
import os
from drun.core import request

response, _ = request(
    "https://api.telegram.org/bot" + os.environ["TELEGRAM_TOKEN"] + "/getUpdates",
    {"allowed_updates": ["message"]},
)
for update in json.loads(response)["result"]:
    chat = update.get("message", {}).get("chat", {})
    if chat.get("type") == "private":
        print(chat["id"])
'@ | .\.venv\Scripts\python.exe -
```

4. Запишите ID своего чата в `TELEGRAM_CHAT_ID` и запустите `.\.venv\Scripts\python.exe -m drun serve`. В стартовом логе должно появиться `"telegram": true`. Отправьте боту «Покажи дерево рабочей папки», затем «Напомни мне через две минуты проверить Drun». Для доставки напоминания сервер должен оставаться запущенным. Если команда не вывела ID, отправьте боту новое личное сообщение и повторите.

### Остальные настройки

| Возможность | Настройка |
|---|---|
| Telegram | `TELEGRAM_TOKEN` и числовой `TELEGRAM_CHAT_ID` личного чата владельца. Запустите бота в Telegram и отправьте сообщение. |
| Напоминания | Попросите напомнить в конкретную дату и время. Сервер доставляет наступившие разовые напоминания через Telegram. CLI показывает наступившие напоминания по запросу. |
| Поиск | `BRAVE_API_KEY` для Brave Search API. Ответ инструмента включает ссылки. |
| Личный календарь | `PERSONAL_ICS` с приватной ссылкой iCalendar или путём к локальному экспорту. |
| Внешний календарь | `EXTERNAL_ICS` с отдельной подпиской iCalendar. Чтение событий за день с учётом повторений и `DRUN_TZ`. |
| GitHub | Чтение открытых issues по `owner/repo`. Для закрытых репозиториев задайте `GITHUB_TOKEN` с доступом на чтение issues. |
| MCP | `DRUN_MCP={"example":{"url":"http://127.0.0.1:9000/mcp","headers":{}}}` в одну строку. Поддерживается Streamable HTTP с JSON и конечными SSE-ответами. Серверы подключаются при старте. |

Для Google Calendar откройте настройки нужного календаря и найдите секретный адрес в формате iCal. Можно также указать абсолютный путь к экспортированному файлу, например `PERSONAL_ICS=C:/Users/your-name/calendars/personal.ics`. Для внешнего календаря используйте ссылку или файл расписания в формате ICS. Проверьте запросом «Покажи личный и внешний календарь на завтра».

Для веб-поиска создайте ключ в [Brave Search API](https://api-dashboard.search.brave.com/documentation/guides/authentication). Проверьте условия тарифа перед подключением. Для первой проверки GitHub используйте публичный репозиторий, например «Покажи открытые issues psf/requests». Токен для закрытых репозиториев можно ограничить выбранными репозиториями и разрешением `Issues: read`.

## Архитектура

- `drun/agent.py` собирает системный контекст, передаёт модели JSON-схемы, исполняет `tool_calls` и возвращает результаты с исходными идентификаторами вызовов. Файловые операции ограничены каталогом `workspace/`. Вложенные `AGENTS.md` загружаются по пути к файлу. Навыки обнаруживаются в `workspace/skills` и `workspace/.agents/skills`, полное тело загружается при активации.
- `drun/core.py` проводит чат, compaction и эмбеддинги через LiteLLM. Маршруты `assistant` и `memory` определены в `litellm.yaml`. Приложение резервирует токены до запроса, затем сохраняет usage из ответа модели. Прерванные и неуспешные вызовы учитываются по резерву. Оценка входа консервативная и основана на размере JSON в UTF-8. Бюджет накопительный для текущей БД.
- SQLite хранит диалог полностью. Когда история перестаёт помещаться, старые пары сообщений сворачиваются в сохранённое резюме. Явно сохранённые факты хранятся с эмбеддингами и извлекаются по косинусному сходству.
- `bash` и PowerShell 7 работают внутри Linux-контейнера на Windows, Linux и macOS с Docker. Команды получают `workspace/` только для чтения и временный `/tmp`. Сеть отключена, ресурсы и время работы ограничены. Сохранение файлов проходит через отдельный инструмент. Подключёнными MCP-серверами и их окружением управляет владелец.
- Структурированные JSON-журналы пишутся в stderr. Поле `trace_id` связывает запуск задания, вызовы шлюза, инструменты и compaction. Для отправки трассировок в OpenTelemetry Collector задайте `OTEL_EXPORTER_OTLP_ENDPOINT`, например `http://127.0.0.1:4318`. Дашборд и команда `usage` показывают накопительный расход по моделям и статусам.

## Сценарий защиты

1. В Telegram попросите запомнить факт, например «Для проекта Drun день демонстрации — пятница», затем спросите о нём в CLI.
2. Попросите показать иерархию и инструкции рабочей папки. Создайте тестовый файл, затем прочитайте его через Bash и PowerShell.
3. Попросите выполнить навык `daily-brief`, найти источник в интернете и показать issues выбранного репозитория.
4. Создайте напоминание на ближайшие минуты и проверьте доставку в Telegram. Откройте дашборд и сопоставьте журнал с результатом.

Исходники, конфигурация и этот сценарий составляют артефакт работы. `.env`, персональная БД и содержимое пользовательской рабочей папки исключаются из Git.

Форматы инструкций и навыков описаны в [AGENTS.md](https://agents.md/) и [Agent Skills](https://agentskills.io/home).
